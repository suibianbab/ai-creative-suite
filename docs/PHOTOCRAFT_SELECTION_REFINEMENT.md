# PhotoCraft 选区精修验证

日期：2026-10-11；固定版本 PhotoCraft 0.6.0。

## 实现

Image Studio 工作台允许在主套索/采样/矩形选区上追加最多 8 块原生 PhotoCraft 套索修正，每块为“补选”或“剔除”。用户可撤销最后一点或最后一块修正。边缘扩展/收缩范围为 -20～20 像素，羽化范围为 0～8 像素。桥接按顺序执行主选区、扩展/收缩、可选的面料颜色交集、增减套索、羽化、标签保护框，最后创建带蒙版的调整图层。所有参数和坐标在桥接端重新校验；预览不写入项目，应用才保存可编辑 `.pcraft`。

当帽沿套索略微落在面料内侧时，可先扩展边缘，再提供亮部/暗部面料取样点，让 PhotoCraft `select.colorRange` 与扩展的选区相交。补选和剔除修正排在颜色交集之后，允许用户修复被颜色匹配漏掉或误选的局部。标签保护框最后减去，以免边缘扩展重新覆盖标签。

## 样图结果

自制 `qa/fixtures/photocraft-hat-teal.png` 的帽沿内侧套索：在固定候选区域的 8289 个蓝绿色面料采样像素中，基础选区换红 8131 个；扩展 10 像素、增减选区并补充面料取样后为 8274 个。中性背景/阴影变化采样点从 796 降至 243。增减选区与无修正版本有 1774 个采样位置产生差异。标签、帽身和远处背景的指定像素保持原值；无效修正模式与超界扩展被拒绝。量化回归见 `scripts/photocraft/test_selection_refinement.py`。

浏览器实测补选、剔除、取样、边缘参数、保护框、预览、应用、原生保存和刷新重开。一次剔除轮廓切掉了帽沿右侧；取消预览并撤销该块后恢复。视觉检查仍能看到帽沿下方暗红溢色和少量边缘残留。**本样图的交互闭环通过，精品修图视觉验收未通过。** 当前计数是这张自制图的启发式区域指标，不能代表真实商品图总体成功率。

## 后续验收

需要至少在真实授权的细发丝/毛绒边界、透明或反光商品以及印花/商标边界上检查全分辨率预览，并记录背景污染、目标色残留和人工修正时间。对复杂边缘应使用 PhotoCraft 官方画布的专业蒙版工具精修；若 PhotoCraft 0.6.0 在代表性素材上无法达到质量门槛，再评估上游版本或 AI 分割 Provider，不在平台另建完整画笔引擎。

2026-10-11 已补充 CC0 毛绒猫图压力测试与 Web 画布蒙版精修闭环，详见 `qa/UI-015-2026-10-11.md`。猫耳换色出现硬矩形背景污染，判定失败；PhotoCraft CLI 的黑白蒙版笔触可逆，但 Web 画布的白色补画尚未稳定验证，不能把画布入口等同于专业质量达标。

更正：PhotoCraft 0.6.0 自带 `select.object`、`select.subject` 和 `select.refineEdge`。旧测试并未使用它们。Image Studio 现增加“PhotoCraft 智能选物体”模式，用用户画框调用 `select.object` 和 `select.refineEdge`，再走原生可编辑调整层、预览和保存流程。自制帽图的原生智能选物体测试覆盖 8264/8289 个蓝绿色面料采样点，中性区域变化 14 点，优于旧手动画框配方；此结果不能代表毛发效果。见 `scripts/photocraft/test_native_object_selection.py`。

同一帽图尝试较小的边缘扩展：4 像素扩展、2 像素羽化时，目标色覆盖 8217/8289，背景/阴影变化采样点 77；原先 10 像素扩展为 8274/8289 和 243。扩展越大，青色边缘越少，但红色溢入阴影越多；这是针对单一合成样图的取舍，不能设置全局“最优”扩展值。用户应在全分辨率预览中选择并修正。当前两个版本都有可见边界瑕疵。

2026-10-11 实测发现：一次“预览成功”仅改变 19×19 像素范围、141 个像素，肉眼看不出换色。PhotoCraft 的 `select.object` 对极小画框仍可返回 `selected: true`，因此仅检查有无选区不足以判定编辑有效。工作台现对整帽/帽沿画框做面积提示；桥接在智能选物体和精修之后再次检查选区范围，过小则拒绝生成成功预览。`IMG-010` 增加极小选区回归。此保护只避免误报，不替代目标语义与边缘质量验收。

2026-10-11 后续：在同一猫耳图上对比 PhotoCraft `select.object` 画框与 `select.refineEdge` 参数。紧画框 `[1440,210,270,310]` 能返回选区；较宽的 `[1390,150,390,440]` 返回空选区，不能只靠扩大画框解决复杂边缘。将精修半径由 3 提到 12，叠加平滑、羽化和收缩后，预览中的耳根硬截断仍在。实验文件保存在 `.tools/photocraft-selection-qa/cat-refine-*`，**毛绒自动边缘质量仍未通过**。

补测 PhotoCraft `select.subject` 加原生 `select.refineEdge`：能选出猫主体，但同时把左侧毯子大面积误选，换色预览 `.tools/photocraft-selection-qa/cat-subject.png` 出现明显背景污染。因此本版本不能将“选择主体”直接作为毛绒图的一键方案。

为让局部精修可操作，工作台预览新增 1×/2×/4× 放大、黑色剔除及白色补回笔刷，均调用 PhotoCraft 原生 `paint.stroke` 的 `target: mask`，不自行修改图片像素。每笔生成新的 `.pcraft` 和预览；上一个不可变预览作为撤销来源。桥接只允许对当前可编辑调整层蒙版操作，并检查图片边界和笔刷参数。`IMG-012` 验证帽沿黑/白笔触像素可逆、源文件可编辑、旧预览不变；浏览器验证两种笔刷、撤销、应用、保存和刷新重开。此功能解决人工补选/剔除路径，不意味着 PhotoCraft 0.6.0 可自动产生精品毛发蒙版。仍需在真实复杂素材上记录人工精修时间和全尺寸视觉验收。

追加 PhotoCraft `select.quick` 猫耳实验：该命令选到了外围深色背景；和 `select.subject` 误选毯子、`select.object` 截断耳根的结果一起说明当前固定版本的三种自动选区均未通过这张毛绒图的视觉 QA。原始实验预览位于 Git 忽略的 `.tools/photocraft-selection-qa/`。复杂边缘后续应先评估 PhotoCraft 上游改进与专业蒙版人工流程，必要时接入独立分割 Provider；平台不复制其选区引擎。

2026-10-11 隔离试用官方 [PhotoCraft 0.7.0](https://github.com/storytold/photocraft/releases/tag/v0.7.0) CLI，没有替换固定的 0.6.0。相同猫图的紧框 `select.object` 只选中耳尖；宽框返回空选区；`select.subject` 又把毯子纳入。现有本机 BiRefNet Provider 能分离猫与毯子。工作台新增“AI 边缘蒙版 → PhotoCraft”：Provider 只给出主体灰度蒙版，PhotoCraft 原生 `select.loadSelection`、矩形相交和调整层保存执行实际编辑；画框内侧羽化可调。桥接检查蒙版尺寸与非空选区。`IMG-015` 在 JPEG 和 `.pcraft` 两种输入上验证耳部变化、远处背景不变、输出有原生可编辑蒙版。`UI-020` 浏览器预览和 PhotoCraft 画布应用流程通过，但整只目标耳朵的绿色突兀，耳根连接和细毛也不自然，毛绒视觉质量验收失败。

首次矩形框样片把耳朵下方和眼睛上方的毛也涂绿。现增加 PhotoCraft 原生套索与 Provider 主体蒙版相交，可沿耳轮廓点选。`IMG-015` 追加耳部多边形样片：眼睛附近和远处背景抽样不变，绿色集中在单侧耳朵。两种范围均保留，矩形适合规则区域，轮廓适合不规则局部。

用户复核指出，画面右侧（猫自身左侧）的**整只目标耳朵**变成突兀的绿色，不能把问题缩小为耳根过渡线。已在 PhotoCraft 原生调整层对比固定着色、较低饱和度、Color 混合和色相偏移。Provider 换色默认改为饱和度 35 + Color 混合，测试确认耳内原有明暗对比保留，但整耳绿色仍明显，耳根连接和细毛也未达到自然效果。本例的选区路由与可编辑性通过，**视觉质量验收失败**；后续必须按全耳颜色、毛发纹理、耳根衔接、边缘污染四项检查，不得只用远处背景像素不变或边缘羽化值代替视觉判断。见 `qa/UI-020-2026-10-11.md`。

曾尝试将 PhotoCraft 原生 `select.colorRange` 与 Provider 耳朵蒙版相交，但新样片留下大块橙色，无法满足完整耳朵换色，已回退强制取样和颜色范围交集。当前仍由 PhotoCraft 完整调整层蒙版换色，并用 Color 混合保留毛发明暗；`IMG-015` 增加耳根必须换色的断言。整耳覆盖恢复，但耳根衔接与细毛边缘仍需精修，不能宣称精品效果已通过。
