# 关键镜头双候选（B）设计

日期：2026-10-22
状态：设计已定（决策由 Claude 按用户授权代定；实现前仍以本文件为准）
上游：`docs/VIDEO_STUDIO_LAPER_STORY2BOARD_DESIGN_INPUT_2026-10-21.md` §2 候选 B、§3 验收 2；ADR 0003（内容版本模型）、ADR 0012（平台/编辑器边界）
范围：Video Studio 分镜编辑工作台，P0 本地项目

## 1. 意图与为什么

审片时导演对 1–2 个关键镜头想看到两种拍法并比较权衡。今天能做的事是「重做一次 → 看版本下拉 → 再重做 → 回滚」，但三样判断信息分散在三处：拍法理由在版本下拉的截断文字里，时长在卡片摘要里，对整片帧数的影响只有在编辑表单里改时长时才出现。结果是用户要靠记忆在多个版本之间来回翻。

B 只补「两个候选并排看 → 选定 → 回到唯一工作版本」这一步。它不引入新的文档概念：候选就是既有不可变内容版本，选择就是移动 `workingVersionId`。零 schema、零新事件类型、零 ADR 变更。

## 2. 目标 / 非目标 / 反目标

**目标**

- 有 ≥2 个内容版本的镜头，可在镜头卡内并排比较两个候选。
- 每列显示：版本序号与状态、拍法说明（`ContentVersion.description`）、时长、以及「选它之后整片帧数 `before → after`」。
- 选定候选 = 切换工作版本；锁定镜头允许（ADR 0003 §1.3 人工路径），留痕。
- 选择前拦下会让整片不可量化的候选（新造零帧），文案与 C 一致。
- 保存并重开项目后，工作版本仍是所选候选。

**非目标**

- 不生成画面草图、缩略图或图片；不调用任何模型、TTS 或付费接口。
- 不新增「关键镜头」标记字段、候选分组字段或候选理由字段。
- 不做 N 列对比（上限两列）。不要求每个镜头都有候选。
- 不改审批/锁定语义：选用候选不会自动 `approved`。

**反目标**（即使功能可用也算失败）

- 出现第二个编辑器或第二条时间线。
- 对比视图成为选版本的唯一入口——版本下拉与「回滚到此版本」必须继续可用。
- 把模型给出的拍法说明当成画面质量或一致性的证据。
- 为对比而静默改写其它镜头。

## 3. 约束

- **单一事实源**：候选 = `shot.contentVersions`；选择 = `workingVersionId`；留痕 = `shot.events`。派生状态只用 `deriveStatus`，不落库。
- **帧数口径与渲染同源**：整片帧数前后对比直接复用 `describeDurationImpact`，拦截用 `durationApplyError`；不另写帧数学。
- **零计费**：不运行 TTS，不传 `--narration`；不新增网络依赖。
- 用户可见文案全部中文；沿用既有 `shot-*` 样式与卡片布局。
- 只在隔离工作树内改动；不碰主检出。

## 4. 设计

### 4.1 数据流

- 候选列表：`candidateSummaries(shot)` 从 `shot.contentVersions` + `deriveStatus` 生成，序号与现有版本下拉一致（1 起）。
- 默认对比对：左 = 当前工作版本；右 = 最新的非工作版本（`contentVersions` 中最后一个非工作项）。少于两个版本时没有对比入口。
- 每列可换成该镜头的任意其它版本（两列可互换，同一版本不允许同时占两列——右列下拉排除左列当前值，反之亦然）。
- 选用：`describeDurationImpact(project, index, candidate.durationMs)` → 若 `durationApplyError(impact)` 非空则拦住并显示；否则调用既有的 `rollbackWorkingVersion(document, shotId, versionId)`。
- 工作版本变化后，对比面板重置为默认对（含「应用修订」「重做」「回滚」任一路径）。

### 4.2 UI

镜头卡版本行新增「对比候选」开关，仅 `contentVersions.length >= 2` 时渲染。展开后为两列面板：

| 列字段 | 内容 |
| --- | --- |
| 标题 | `候选 A` / `候选 B` + `#序号` + 状态（草稿/候选/已批准） |
| 版本选择 | 该镜头全部版本的下拉，排除另一列当前值 |
| 拍法说明 | `description` 原文，不截断（最长 200 字） |
| 时长 | `${durationMs / 1000}s`（与卡片摘要同格式） |
| 整片帧数 | 候选即工作版本时显示「当前 N 帧」；否则 `N → M 帧`，无法量化一侧显示「不可量化」 |

每列底部「选用此候选」按钮；工作版本所在列禁用。面板底部固定一行说明：「说明来自版本记录，不代表画面质量；选用只切换工作版本，不改变审批状态。」

新增样式类：`.shot-compare-toggle`、`.shot-compare-panel`、`.shot-compare-column`、`.shot-compare-select`、`.shot-compare-choose`。沿用现有灰阶与圆角。

### 4.3 校验与错误

- 版本不存在或只有一版：不渲染对比入口/对应列，不抛错。
- 候选时长使整片新造零帧：`无法应用：…`，文档不变；存量零帧项目按 C 的「零帧集合严格缩小且无新增」规则允许逐镜修复。
- 转场借帧 `transitionIssue` 只提示不拦（与 C 一致，出片期 fail-loud）。
- 审批状态不因选用变化；若所选版本未批准，状态列如实显示「候选」或「草稿」。

### 4.4 与既有能力的关系

- **单镜重做**（`addCandidateVersion`）仍是产生候选的主要入口，B 不复制其逻辑。
- **版本下拉 + 回滚**保留；B 只是把比较信息集中到一处。
- **A2 镜头说明**是候选理由的载体；B 不新增理由字段。

## 5. 验收样例（江南园林，6–8 镜头）

1. 对第 3 镜（月洞门外低机位向内推进）重做一次得到候选 B（不同组件/时长）；打开「对比候选」→ 两列说明不同、时长不同、整片帧数有 `before → after`。
2. 选用版本 #1（原拍法）→ 工作版本回到 #1；版本下拉与对比面板都显示 #1（工作）。
3. 保存、刷新、从项目列表重开：`workingVersionId` 仍为 #1，两个版本都在，审批状态未变。
4. （单元覆盖）把候选 B 的时长改成会新造零帧的值 → 选用被拦，文档不变。

## 6. 证据口径

- 单元：`candidate-compare` 纯函数（摘要、默认对、列互换排除、与 C 闸门组合的拦截）。
- 浏览器回归：新增 `scripts/video/e2e-candidate-compare.mjs`（QA `VID-027`）：重做产生候选 → 对比 → 选用另一候选 → 保存 → 重开校验。
- **不进证据**：画面相似度、生成质量、模型理由的真实性。

## 7. 留给实现者的判断

- 面板在两列内的具体排布、间距与响应式（沿用现有卡片栅格）。
- e2e 用几个镜头、重做指令的具体文案。
- 是否额外显示时长差的绝对值（可选，不影响验收）。

## 8. 决策记录（Claude 代定，用户授权「按你的判断做」）

1. **候选 = 既有内容版本，零 schema。** 设计输入明确「优先复用现有字段，不立即扩核心 schema」；版本模型已能表达两候选，选择记录已有 `audit` 事件。新增字段只会制造第二事实源。
2. **对比上限两列。** 设计输入给的上限；N 列会让 P0 卡片过载，且超过两选的决策并不是本阶段要解决的问题。
3. **不出图、不调模型。** P0 没有逐镜画面预览管线，出图引入费用与不确定性，违背零计费与「不把模型理由当证据」的约束。权衡用说明 + 时长 + 帧数表达。
4. **选择走 `rollbackWorkingVersion`。** 它已经就是「移动工作指针 + audit 留痕」，语义完全吻合；新 op 会重复校验与事件逻辑。
5. **选择前跑 C 的时长闸门。** 换候选实际改变该镜时长，不拦会重演「零帧 → 渲染期崩溃」。复用 `describeDurationImpact` 保持与渲染同源。
6. **不新增「关键镜头」字段。** 对比入口按版本数出现，验收时人工挑 1–2 个关键镜头走一遍；持久化「哪些是关键」没有下游消费者。
