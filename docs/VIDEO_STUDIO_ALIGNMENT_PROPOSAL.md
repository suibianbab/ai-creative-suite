# Video Studio 目标与功能对齐草案

状态：讨论稿，待用户确认与 Claude 评审；不代表实施顺序或已交付能力。

依据：`PRODUCT_ARCHITECTURE_ALIGNMENT.md`、ADR-0012、`AI_Creative_Suite_Dev_Pack_v3/PROJECT_SPEC.md` 的创意流程与验收目标。旧文档中“自建完整 MotionDocument/HyperFrames 默认承载所有场景”的表述，以 ADR-0012 的专业编辑器复用原则为准。

## 1. 产品目标

Video Studio 面向多题材视频制作，不限定商品广告。用户从要求、素材和参考开始，制作可修改的分镜与镜头，完成动画或剪辑，审片后导出横版、竖版等成片。目标内容包括：

| 内容类型 | 用户希望完成的事情 | 可编辑交付物 |
| --- | --- | --- |
| 文字、Logo、品牌动效 | 设计排版、节奏、入场/转场，修改文案和关键帧 | 动效编辑源、分镜、成片 |
| 数据、STEM、地图解说 | 用准确数据和图形说明概念，配旁白与字幕 | 数据/来源、场景源、分镜、成片 |
| 教程、录屏、访谈、社媒剪辑 | 导入实拍素材，剪切、重排、加字幕、配乐和动态图形 | 剪辑工程、素材引用、成片 |
| 图片 2.5D | 前中后景分层、相机视差和遮挡修补 | 分层素材、场景源、成片 |
| 商品广告与写实 3D | 使用准确资产做产品表现、灯光和镜头运动 | 模型与 `.blend`/场景源、成片 |
| AI 叙事预演 | 锁定角色和场景设定，逐镜头生成、替换和审片 | 分镜、素材/模型来源、镜头版本、成片 |
| 交互动画与 Web 3D | 在事件或状态变化时播放动画，可嵌入网页 | 可运行、可编辑的交互源；视频仅是可选输出 |

参考 SVGAnimate、Hera、Jitter、Rive、Spline、LTX Studio 的内容类型、制作体验与质量目标。参考产品不是等价功能承诺；每种能力以本项目真实样片和可编辑源验收。

## 2. 用户工作流与功能范围

1. **项目与要求**：选择内容类型、用途、时长、横竖版、语言；录入目标、受众、品牌限制、必须保留的素材与参考。素材记录来源和授权状态，原件不覆盖。
2. **创意规划**：形成若干风格方向、色板、字体、画面和运动参考；用户选定后保存为项目级 Style Bible。品牌约束单独记录，不让后续自动生成静默覆盖。
3. **分镜**：每个镜头有时长、画面描述、解说/字幕、镜头运动、转场、素材引用、目标引擎和状态。可新增、删除、复制、拆分、合并、重排、锁定与逐镜头重做。锁定镜头禁止 AI 自动改写；人工修改仍需明确可见。
4. **场景制作**：按镜头内容调用合适编辑器或程序化场景路径。用户能回到原生编辑源继续调整。跨引擎共享的是素材、镜头状态、预览和交付记录，不强求统一图层/关键帧内部格式。
5. **审片与修改**：按镜头查看预览和整片；可指出“第 3 镜头文字太快”之类的修改要求。系统只修改指定范围，保留锁定镜头和已批准素材，记录版本差异。
6. **成片交付**：组合镜头、旁白、音乐、字幕并导出目标尺寸。保留项目、各镜头可编辑源、素材来源、渲染参数和质量记录；重新打开后可以继续修改。

自然语言的角色是把用户意图转为**可检查的项目、分镜或编辑器操作计划**，再由相应引擎执行。模型不直接写第三方编辑器内部文件，也不把生成视频当作唯一项目源。

## 3. 架构与引擎分工

```text
用户 Brief / 品牌 / 素材 / 参考
             ↓
平台项目：风格方向、分镜、镜头状态、资产与版本
             ↓
镜头路由 + 编辑器适配层
├─ VectorCraft：图标、SVG、矢量素材候选
├─ EffectCraft：传统 2D 动效与关键帧编辑候选
├─ FilmCraft：多轨剪辑、字幕、音频和人工精修候选
├─ HTML / SVG / GSAP / D3 / Three.js：程序化数据、STEM、Web 场景
├─ Blender：写实产品 3D 与离线镜头
├─ Rive / Spline：交互动画、交互 3D 专项候选
├─ AI Provider：图像、视频、2.5D 或 3D 候选素材
└─ PhotoCraft：可选的源图片编辑，不是 Video Studio 运行前提
             ↓
镜头预览 / 人工修改 / 版本审查
             ↓
FilmCraft 或 Remotion 成片编排（依场景验证后定分工）
             ↓
画面、文字/数据、身份一致性、音频、导出 QA
```

平台自有：项目、分镜、镜头清单、素材引用、品牌与风格约束、版本、权限、任务、质量与交付记录。专业编辑器拥有各自的画布、图层、关键帧、时间线和原生工程。平台只建立带版本的适配接口及源文件引用，不平行开发一套完整动效编辑器或视频剪辑器。

EffectCraft、FilmCraft、VectorCraft 当前仍是**待验证集成候选**。接入前需核实许可与部署方式，并完成“导入素材 → 真编辑 → 保存源 → 重开续编 → 导出/渲染”的代表性样片。若某候选无法满足该闭环，再决定对应内容类型的替代路径。既有 Remotion 和 Blender 样片验证了局部技术路径，不等于 Video Studio 工作流已交付。

## 4. 质量与验收口径

每类内容至少有一条代表性端到端样片，记录输入素材、引擎版本、可编辑源、导出结果、失败点和人工审片结论。功能状态分别标为：**已实现、仅样片验证、规划中**。

- **动效**：文字可读、节奏可调、关键帧/效果可在原生编辑器继续改；横竖版分别检查，不靠简单裁切代替版式设计。
- **数据/STEM**：数字、单位、时间、地图或科学说明可追溯到输入来源；动画不能改变事实含义。
- **剪辑**：源视频可重排，字幕和音频能独立修改；导出后检查画面、声音、字幕同步。
- **2.5D**：检查分层边缘、遮挡修补、相机运动中的露底与拉伸。
- **产品 3D**：准确模型、材质与产品身份是前提；有模型时验证灯光/运动/渲染，只有单张图片时另列真实性上限。
- **AI 叙事**：逐镜头检查角色、服装、场景和运动连续性；支持只重做失败镜头。
- **交互**：实际触发状态/事件并可嵌入；仅导出 MP4 不算通过。

一段视频渲染成功不代表质量通过。商业级结果需要人工审片结论；未验证的自动生成质量不能作为产品承诺。

## 5. 需要用户与 Claude 评审的问题

1. 对外统一名称用“Video Studio”，还是保留“Motion Studio”并以视频为主要交付？名称不改变上述多题材范围。
2. 风格方向、Brand Bible、分镜锁定与逐镜头版本是否符合期望的控制粒度？是否有必须加入的用户操作？
3. 传统动效与剪辑是否以 EffectCraft / FilmCraft 的可编辑源为首选，并在真实桥接样片后才确定正式集成？
4. 程序化 HTML/SVG 场景与交互源是否应作为独立交付类型，而不是都压成视频？
5. 对视频生成模型，是否接受“候选镜头 + 人工审片 + 单镜头重做”的产品定位，而不承诺全自动成片？
6. 每类目标样片的质量门槛与可编辑源要求是否需要调整？

此草案只对齐**要做什么、由谁做、怎么验收**。功能先后顺序、具体接口与工期在评审结束后另定。
