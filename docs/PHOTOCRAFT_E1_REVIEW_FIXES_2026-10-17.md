# Codex 复审整改记录：D/E 入口、浏览器验收与 A/B 门槛

本记录对应第七轮交付的复审问题。此前 `attempt 7 failures=0` 只验证浏览器操作和预览生成；花蕊误染、左耳双耳与额头大面积误染并未纳入失败条件。此前文档把 IMG-056 写为浏览器验收也不正确：IMG-056 实际是生成模型 A/B。

## 已修改

1. `parts-candidates.py` 的画框模式将 SAM 原始蒙版裁到用户框内，再计算面积、去重、排序、轮廓与 PNG。原蒙版有超过 25% 面积在框外时，不把“整物体被小框截断”的区域当作可确认候选。无框网格模式不变。这个限制解决了页面“只按框内范围”与实际返回蒙版可能覆盖双耳的契约冲突；它不保证框内一定只含目标，也不保证整个部件被完整选中。
2. 页面单候选不再显示误导性的“100% 匹配”；候选确认消息提示原尺寸检查漏选与邻近区域，并引导使用现有 PhotoCraft 蒙版笔刷补回或剔除。
3. 浏览器脚本及其 :3100 代理、:4112 origin shim 移到可跟踪的 `scripts/photocraft/`，使用仓库相对路径和根包 `playwright-core` 依赖；IMG-057 登记为 `browser-image` tier，IMG-058 顺序读取四张全分辨率渲染并刷新区域差分报告，`pnpm qa:browser-image` 可复跑。单例运行写 `.subset.json`，不覆盖全量报告。删除蒙版故障注入只移除临时 `candidate-mask.png` 文件。
4. IMG-057 把操作链路和质量指标分开：花瓣编辑先记录未修时花蕊变化，再用 PhotoCraft 现有蒙版笔刷模拟人工剔除，并验证花蕊平均 RGB 变化 ≤8/255；左耳验证用户框外平均变化 ≤0.5/255。框内是否覆盖完整耳朵仍列为 UI-038 人工验收，不能由框外隔离指标代替。
5. IMG-056 的 A/B 脚本只有四个预定模型×操作臂全部成功才返回成功；mask 接口探针仍单独如实记录。该门槛有 3 条独立单测，未重复付费生成。

## 实测

- `test_parts_candidates_box.py` 3/3、`generation-ab-status.test.mjs` 3/3、`target-entry.test.ts` 11/11、全仓 Biome、五个 workspace TypeScript typecheck 通过。
- `qa:validate`：67 automated / 42 manual。
- IMG-055 在新画框契约下全量 12/12 执行成功：grid top-1 mask IoU mean 0.3072，box 0.6916；box best mean 0.8155；改善 9、持平 1、回退 2。模拟框是 GT 标注框，并非用户实画；该数字只说明框提示潜力，不能推出商业精修质量。
- IMG-057 真实浏览器四条链路重跑：花蕊未修时平均 RGB 变化 94.87/255，经 PhotoCraft 两笔黑色蒙版擦除后降至 0.261/255；左耳框外平均变化 0.021/255。左耳预览已覆盖主要耳面，并用 PhotoCraft 两笔蒙版擦除减轻耳根蓝色突起；**耳根仍有可见硬边，UI-038 全尺寸商业精修验收不能记为通过**。本次 IMG-057 PASS 仅覆盖交互、框外隔离、花蕊经人工接力后的精修与套索降级。

## 交付边界

画框限定和“候选环供人挑”保留为安全入口。精确部件分割仍受本机 SAM+CLIP 候选质量限制；用户需查看完整蒙版，必要时用 PhotoCraft 蒙版笔刷补选/擦除，或保存待精修。`TAU_AUTO_ENABLED=false`、生成模型默认值都未改变。`artifacts/` 下的 JSON 报告可跟踪；大幅 PNG/JPG 默认仍被忽略，关键对比截图另存于 `qa/evidence/photocraft-e1-2026-10-17/` 供复审。
