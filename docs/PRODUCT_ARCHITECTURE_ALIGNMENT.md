# AI Creative Suite 目标与架构基线

状态：目标已由用户确认；日期：2026-10-10。本文记录目标和技术架构方向。具体引擎接入、质量与工期仍以样片验证为准。与旧 PhotoCraft 可选/原生完整画布等条款冲突时，以 [ADR-0012](../AI_Creative_Suite_Dev_Pack_v3/docs/adr/0012-reuse-professional-editors.md) 为准。

## 一、产品目标

1. Image Studio：用户可通过自然语言和专业画布编辑图片。PhotoCraft 是拟采用的主图片编辑能力；生成式修改由可替换的 AI 模型提供。图层、蒙版、调色等高级编辑应尽量复用已有引擎，不继续研发一套完整的平行图像编辑器。现有原生画布是早期原型，不能被当作最终自然语言修图目标已经实现。
2. Video/Motion Studio：服务多种题材，包括文字动效、数据/STEM/地图解说、品牌内容、教程/录屏、访谈与社媒剪辑、照片 2.5D、商品广告、3D 视频、AI 叙事预演及交互内容。商品广告是重要场景，不限定产品范围。
3. 所有主要结果尽可能保留可编辑源、素材来源和版本；提供分镜与逐镜头修改、多尺寸交付。参考 SVGAnimate、Hera、Jitter、Rive、Spline、LTX Studio 等产品的内容类型、体验与质量标准，不把接入某个引擎视为这些标准自然达成。
4. 视频质量通过代表性样片和人工视觉评审判断。准确 3D 模型可进入 Blender 写实产品渲染路径；单张产品图的 3D 真实性上限必须单独说明。模型生成内容的连贯性和真实感不得承诺超过实测结果。
5. Cloud、Enterprise、AirGap 共用代码基线；原始素材不可覆盖，租户、权限、积分、沙箱和可追溯性保持既有约束。

## 二、拟定的制作架构

```text
用户 Brief / 素材 / 品牌 / 参考
              ↓
创意规划 → 风格方向 → Storyboard / 镜头锁定
              ↓
按镜头或任务选择引擎
├─ PhotoCraft：图片编辑和可编辑图层
├─ VectorCraft：SVG、图标、矢量图形
├─ EffectCraft：2D Motion Graphics、关键帧与特效
├─ FilmCraft：多轨视频、字幕、音频和人工剪辑
├─ SVG / HTML / GSAP / D3 / Three.js：程序化数据、STEM 和交互场景
├─ Blender：写实 3D、产品材质和高质量离线镜头
├─ Rive / Spline：交互动画或交互 3D 的专项候选
└─ AI 模型 / ArtCraft 主应用：生成图像、视频或 2.5D/3D 候选
              ↓
成片编排与导出（FilmCraft 或自动化 Remotion，按项目需要分工）
              ↓
画面、内容准确性、品牌/商品身份、音频和导出 QA
```

平台自有数据包括项目、镜头、素材引用、编辑器原生源文件引用、版本、权限、品牌、任务和交付记录。专业画布或时间线的图层、关键帧、效果等内部数据优先交给相应编辑器管理。桥接可行性须经保存、重开、继续编辑和渲染验证后，才替换既有原型。不得同时维护两套完整的图片或动效编辑引擎。

## 三、按成果验收，而非按开发 Phase 猜测能力

| 目标类型 | 首个代表性样片及必须证明的能力 |
| --- | --- |
| 自然语言图片编辑 | 商品改色、局部修图、保留标签与纹理；PhotoCraft 实际执行，保存重开仍可编辑 |
| 文字与 Logo Motion | 10–15 秒，专业排版、可调整节奏、关键帧、双尺寸输出 |
| 数据/STEM/地图解说 | 15–30 秒，多镜头、来源可核查的数据、正确讲解、旁白与字幕 |
| 教程/录屏/真人素材 | 原视频导入、删改镜头、动态图形叠加、字幕、混音、再次编辑 |
| 照片 2.5D | 前中后景分层、视差、遮挡修补、相机运动和画面边界检查 |
| Blender 产品 3D | 准确且可用的模型、材质灯光、镜头运动、可编辑 `.blend` 和成片；无准确模型时单列限制 |
| AI 叙事预演 | 分镜锁定、同一角色/场景跨镜头一致性、单镜头重做和人工审片 |
| 交互动画/3D | 状态或事件可触发、可嵌入网页、源文件可继续编辑；不能用导出 MP4 代替验收 |

每个样片都记录引擎版本、素材来源、编辑源、导出结果、失败点与人工评审。首轮每类只需一条能暴露真实问题的完整样片，避免大量重复的形式化测试。

## 四、防止开发走偏的执行规则

1. 每项功能先写一张简短能力卡：用户任务、目标样片、主引擎、编辑源、AI 指令如何落到真实操作、验收结果。对 PhotoCraft/VectorCraft/EffectCraft/FilmCraft 已有的专业能力，默认先评估集成。
2. 开工前核对本草案转正后的目标基线、最新 ADR 与当前实现。若拟开发一套新的画布、时间线或渲染器，先写明现成引擎为何无法承担，并以最小样片验证。
3. 每个开发增量演示用户可见流程，并标注“已实现、仅样片验证、规划中”。功能完成的定义包括可编辑源保存/重开和对应质量检查，不能只以 API/单元测试通过计算。
4. 功能、架构或质量目标发生实质变化时更新 ADR 与目标映射，再实施。例行修复、适配和内部重构由开发推进，不逐项要求用户确认；改变主编辑引擎、删除目标类型或降低验收标准需要向用户展示方案和影响。
5. 每轮开发复核一次目标覆盖表：每个承诺的内容类型都能找到实现路径、当前证据和下一步；发现只围绕商品广告或原生编辑器扩展时，立即纠偏。

## 五、待消除的文档冲突与技术未知

- `PROJECT_SPEC.md`、`DECISIONS.md`、`ARCHITECTURE_PRINCIPLES.md` 等旧文档仍写 PhotoCraft 可选、原生 ImageDocument 为完整编辑源、HyperFrames 默认场景引擎。近期对话已偏向 PhotoCraft 主画布及优先复用 EffectCraft，须正式写新的 ADR 并注明被取代的条款。
- PhotoCraft 0.6.0 已通过开发级 Web 画布导入/保存重开、CLI 真实编辑、工作区云项目版本和限定“帽子改黑”局部修图样片。该 Web 宿主适配依赖固定上游版本，本机 CLI 桥接尚未成为生产任务服务；任意自然语言修图和复杂商品质量尚未验证。EffectCraft、FilmCraft 的 Web/Windows 编辑体验、稳定性和接入方式尚未在本项目验证。验证记录见 [PhotoCraft 集成样片](PHOTOCRAFT_INTEGRATION_SPIKE.md)。
- Remotion 与 FilmCraft 的终片分工、Rive/Spline 可嵌入方式、ArtCraft 主应用的授权及接口，均需专项样片或授权核查后决定。
- 现有 ImageDocument 项目主要属于开发阶段。PhotoCraft 新项目可直接采用新格式，不要求先完成旧项目批量迁移。旧项目及原图暂保留可读取/导出；只有确需在 PhotoCraft 中继续编辑某个旧项目，才评估按需转换。旧画布与 ImageDocument 可保留为临时预览/导出兼容路径，不继续扩展为主编辑器。素材、租户授权、不可变版本和幂等保存等基础能力可复用，但当前项目 API 与数据库校验绑定 ImageDocument v1，接入 PhotoCraft 原生文件时需要调整接口和存储结构。

## 六、执行方式

每个开发任务引用对应目标和验收项，实际结果持续更新，不用过期的 Phase 顺序代替能力判断。重大架构变化记入 ADR，用户可见功能以可编辑样片和质量结果验收。
