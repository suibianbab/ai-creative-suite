# IMG-035: Layered background replacement

## Scope

The development-only background task asks Qwen for an **empty** background image. PhotoCraft keeps original foreground pixels in a duplicate masked layer, places the Qwen background in an independent embedded Smart Object below it, and retains the original layer at the bottom. The optional shadow is PhotoCraft's editable Drop Shadow layer effect. A saved PhotoCraft subject selection takes precedence; otherwise the existing local BiRefNet mask provider supplies a subject mask that is loaded into a native PhotoCraft selection. This segmentation fallback was needed because PhotoCraft 0.6.0 `select.subject` selected the old hat shadow as part of the subject.

## Checks

- `python scripts/photocraft/test_background_compose.py`: three-layer native source, editable foreground mask, original subject pixel preserved, replacement background pixel visible.
- The same regression checks the pre-generation foreground preview, native lasso subtraction, native mask brush correction, prepared-marker handoff into final composition, manual outline selection, optional foreground shadow, and absent-selection rejection.
- `python scripts/photocraft/validate_background_samples.py`: hat, furry cat, and shampoo image reopen as three-layer PhotoCraft documents with original dimensions. Uses one saved Qwen-generated empty beige background to isolate composition quality from generation variance. Requires the local mask service on port 4101.

## Selection correction (2026-10-13)

The workbench now separates foreground review from the paid background generation call. `/v1/prepare-foreground` creates a native PhotoCraft duplicate and editable mask over a neutral PhotoCraft Fill layer. It accepts a saved selection, PhotoCraft `select.object` rectangle, a manual native lasso outline, or the existing segmentation provider; up to eight add/subtract lasso patches are applied before mask creation. The existing native mask brush can then adjust the preview. `/v1/compose-background` consumes this prepared job, replaces the temporary Fill with the Qwen background Smart Object, and preserves the corrected foreground mask. It rejects an unmarked or malformed prepared job. Browser CORS preflight explicitly allows the new headers.

For the shampoo image, a PhotoCraft object rectangle `[1250,350,1450,1800]` still included a partial flower petal. One subtract lasso patch with points `[[1200,1120],[1540,1120],[1660,1580],[1200,1580]]` removed that remnant. The corrected mask preview is `artifacts/background-layer-qa-2026-10-13/shampoo-corrected-mask.png`; the final three-layer native file and PNG are `shampoo-corrected.pcraft` and `shampoo-corrected.png`. The flower is gone while the bottle label and shape remain. The generic drop shadow and source lighting still need art direction for commercial delivery.

Full-size review correction: removing the flower did **not** make the bottle edge acceptable. The neutral mask preview already shows dark/hard edges around the cap, side and bottom; the beige composite exposes dark source-background contamination and a generic shadow. This sample is `needs manual retouch`, not a passed light-background product image. The review and PhotoCraft mask brush are a general correction path, not a bottle-specific automatic fix. Track it with the fur and cat-ear residuals under `docs/PHOTOCRAFT_EDGE_QUALITY_POLICY.md`; replay all of them before adopting an upstream PhotoCraft upgrade.

The hat and cat were also passed through the two-stage provider-selection path (`hat-reviewed.*`, `cat-reviewed.*`). Their output PNGs match the earlier direct-composition samples pixel for pixel. This confirms the review step preserves the existing result until a user actually corrects the mask.

The furry cat remains a **visual fail**: neither the default segmentation nor PhotoCraft's radius-5 `select.refineEdge` recovered fine hair adequately. The preview and native mask brush now allow manual intervention before spending a Qwen call; this test does not claim one-click fur extraction.

The three-layer architecture is functional, but this does not establish general commercial-quality background replacement. For complex fur and multi-object scenes, the UI must keep human selection/mask correction and visual approval in the loop. The PhotoCraft source and all original pixels remain editable for that work.
