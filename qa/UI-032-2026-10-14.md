# UI-032：PhotoCraft 本地草稿与云端版本冲突保护

日期：2026-10-14。改动范围：本浏览器 PhotoCraft 项目缓存与云端项目打开流程。

原因：原实现把 `version = Math.max(local.version, cloud.version)`，随后直接把本地同 ID 项目的 `.pcraft` 字节替换为云端源。若本地版本尚未上传，用户草稿会被覆盖，版本号还可能错误地表示为本地较新版本。

实现：记录 `syncedLocalVersion`，与本地版本比较以识别未上传草稿；旧数据无同步标记时使用保守判断。打开云端版前显示版本冲突选择；选择继续本地草稿时不改缓存，选择云端版时先为本地字节、原图和质量记录创建独立本地项目，再以准确云端版本缓存远端源。上传返回期间若本地出现新版本，不将它误记为已同步，也不把其质量记录附给上传的旧源。

自动回归：`node --import tsx --test ../web/src/app/image-studio/photocraft/local-projects.test.ts`（从 `apps/api` 目录运行），覆盖草稿保留、已同步源更新、旧数据保守保留和浏览器缓存异常记录。4 项通过。

真实浏览器：在云端帽图第 2 版上仅本地保存旋转后的第 3 版，并附「仅用于本地与云端版本冲突验证」的人工精修记录。点击云端第 2 版先出现冲突选择；选择继续本地，重开后仍为第 3 版且备注不变。再次选择云端，工作台创建「本地保留草稿」第 3 版，再打开准确的云端第 2 版。重开保留草稿，质量记录、1254×1254 原生项目均在；再次打开已同步的云端第 2 版不再产生副本。结论：UI-032 通过。
