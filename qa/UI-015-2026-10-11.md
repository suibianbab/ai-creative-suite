# UI-015 PhotoCraft 蒙版精修与毛绒边界

日期：2026-10-11。固定 PhotoCraft 0.6.0；本机开发环境。

## 测试素材

- 自制帽图：`qa/fixtures/photocraft-hat-teal.png`，用于调整层蒙版、保存和重开。
- 毛绒边界：`qa/fixtures/photocraft-fluffy-cat-cc0.jpg`，1920 × 2560，SHA-256 `15b33488c8c1baef278f032b37cc1ced636aee75b65436393e6d6d3ad51431cd`。Wikimedia Commons [Fluffy Cat.jpg](https://commons.wikimedia.org/wiki/File:Fluffy_Cat.jpg)，作者 Flauflauflau，自有作品，页面明确标注 CC0。下载的是页面提供的 1920 像素宽版本；仅用于内部质量验证。

## 浏览器闭环

工作台新增放大 PhotoCraft 画布入口及画布顶部保存按钮。帽沿红色调整层的原生 `.pcraft` 在官方 Web 画布打开；点击调整层黑白缩略图，文档标题显示 `Layer Mask/8`，可用画笔修改。画布保存后，本浏览器项目增加第 1 版，工作台状态显示“预览已更新”；从项目列表重开后，调整层和蒙版保留，局部笔触可见。

PhotoCraft 0.6.0 Web 版没有受支持的宿主消息或控制接口来直接选中蒙版。当前“进入蒙版精修”是放大画布和指引，用户需点击缩略图。测试用黑色画笔在帽沿端点剔除一小块时，可见露出原始青色且保存重开后保留；用 Web 画布白色画笔/橡皮擦恢复同一点未稳定复现，测试项目仍有青色小点。PhotoCraft CLI 对同一调整层蒙版运行黑色后再运行白色 `paint.stroke`，中心像素由原始 `(82,20,21)` 变为 `(22,69,81)`，再恢复为 `(82,20,21)`。因此原生蒙版数据可逆，但 Web 画布的补画交互仍需单独排查，不将本测试算作完整专业精修通过。

## 毛绒边界压力测试

PhotoCraft CLI 对 CC0 猫图右耳执行 `selected-area` 绿色重着色：在 540 × 600 矩形内做 3 个颜色取样，生成可编辑蒙版调整层。预览出现整块绿色矩形，连深色背景、眼睛和白毛也被改色，四周有硬边。产物位于 `.tools/photocraft-selection-qa/cat-ear-green.{png,pcraft}`。本样例明确**失败**，不能作为毛发或毛绒边界质量通过。说明当前取样加矩形不足以自动理解语义对象；复杂边界需要可授权的 AI 分割 Provider 或高质量人工蒙版，再由 PhotoCraft 编辑。

更正（2026-10-11）：上述结论只适用于当时使用的取样加矩形配方。PhotoCraft 0.6.0 原生提供 `select.object`、`select.subject` 和 `select.refineEdge`，桥接层当时未调用。应先验证这些原生能力在毛绒边界上的质量，再决定是否需要外部分割 Provider；不能从旧配方的失败推断 PhotoCraft 缺少通用智能选区。

补测：同一猫图的右耳用原生 `select.object` 加 `select.refineEdge`、紧贴右耳的矩形 `[1440,210,270,310]` 换绿，预览位于 `.tools/photocraft-selection-qa/cat-ear-object-tight.png`。硬矩形污染消失，眼睛与背景保持原样；但耳朵与头部的交界呈人工截断，细毛仍不自然，故毛绒边界精品质量依然未通过。应优先在 PhotoCraft 内调整选区和蒙版；经代表性样片复测仍不足时再评估外部分割 Provider。

## 结论

放大画布、选择原生蒙版、保存并重开、预览同步已验证。精细手动补画的 Web 交互和精品边界质量未通过。保持当前自然语言执行范围受限，不因新增画布入口扩大“任意修图”的产品承诺。
