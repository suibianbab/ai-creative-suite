Status: **cloud round trip and second-account cloud denial passed; local shared-browser privacy failed**. Development localhost and Keycloak only. Reviewer: Codex with the user signed in to the development account.

## Fixture and evidence

- Existing local `hero.png` Image Studio project with one product image and one text layer. Its original source rights were not rechecked for this technical test; no commercial or public use.
- `qa/fixtures/ui003-overlay.png`: locally generated 256×256 transparent PNG, used only as a second image asset.
- Local screenshots: `qa/reports/ui003-cloud-v3.png`, `qa/reports/ui003-cloud-v3-reopened.png`, and `qa/reports/ui003-isolated-account-denied.png` (ignored runtime report directory).

## Observed result

1. Authorization Code + PKCE login completed in the browser. Initial API list returned 401 because the browser token lacked `aud`; the Keycloak mapper used a client audience for a client that did not exist. Changed the mapper to custom audience `acs-api`, obtained a new token, and confirmed the browser cloud list loaded. `AUTH-003` now asserts the example access token's actual audience.
2. Imported the existing local project. The cloud selector showed `hero.png · v1`.
3. Imported the self-created PNG, changed the title to `云端验收 V2 · 原图完整`, and saved. The selector showed v2.
4. Reloaded the page, reopened v2, and observed both image layers and the edited text. Cleared the page token, signed in again through Keycloak SSO, reopened v2, and observed the same three layers.
5. Changed the title to `云端验收 V3 · 重登通过` and saved. The page showed `已保存到云端，版本 3。`; screenshot captured.
6. After the five-minute token expired, a page reload showed `登录工作区` automatically. Signed in through Keycloak SSO and reopened v3; both image layers and the text layer loaded again.
7. Created `acs-dev-isolated` without workspace membership. Its real Keycloak token received 403 for project list and direct project read (`AUTH-004`). Browser login with that account showed `当前账户没有此工作区的访问权限` and no cloud project list. Re-authentication with the original development account restored v3 in the cloud selector.
8. In the same browser profile, the isolated account could still list and open the first account's **local** IndexedDB project, including its original images. This is a separate failed privacy criterion (`UI-004`). The UI now explicitly says local projects are shared within a browser profile; it does not make them account-private.

## Remaining gate

Do not treat local IndexedDB originals as account-isolated on a shared browser profile. An account-private draft design must preserve existing user data before `UI-004` can pass. Cloud access is denied as expected; the independent fresh-context security review and production identity/session design are still required before external exposure.
