# Video Studio W2–W5 后续收口任务（Claude 连续执行）

起点为 `e3887df`，独立分支 `claude/video-studio-closure`。W2–W5 的复核单 `artifacts/handoffs/claude-video-studio-w2-w5-review.md` 是待 Codex 后续复核的基线，保留原分支不变。本单安排可独立推进的后续工作；每个任务完成即提交、记录证据并继续下一个，无须等待用户在线。

## 通用纪律

- 不改 `main`、不合并；只推送本工作分支供复核。保留用户主检出的未提交文件。
- 先读既有契约和真实代码，再作最小改动。不得创造第二套权威时间线、覆盖旧内容版本、静默降低安全闸门，或把推测当实测。
- 每项分别写代码/自动回归/真实操作/视觉质量四态、复跑命令、产物路径和限制。自动测试应覆盖具体失败风险；完成充分验证后停止重复跑门禁。
- 遇到外部资产、设备或人工审片阻碍时，记录阻碍和可人工执行的步骤，继续下一个独立任务。不要为了看似完成而编造许可、真机或人工审片结论。

## C1（最高优先级）：把 W2 导出确认闸门补到服务端

W2 报告指出浏览器 `renderFromWorkbench` 有检查，但直接调用渲染 API 可能绕过。查明所有导出入口及对应请求中的项目/内容/Style Bible 快照；在服务端与真实导出发生前验证代表帧确认所绑定的内容版本、风格版本和摘要。不能只信客户端传入布尔值。旧项目没有该功能时，按已有兼容契约处理并写清适用范围。验证包括直接 HTTP 绕过、确认后改内容/风格、旧版本重开、合法双画幅导出、导出失败无成功交付记录。记录为 `artifacts/handoffs/claude-video-studio-c1-result.md`。

## C2：W5 交换清单的真实时间线与可用媒体

先检查现有无缝帧区间逻辑与 `project.transitions`、垫片、镜头排序、字幕、独立音轨的关系。以现有真实项目建立至少一例带转场的正例、一例损坏区间反例；若转场已经由渲染器合成为帧，清单应准确表示合成后的时间线，并明确编辑器侧可编辑性限制。验证字幕/音轨引用以及素材摘要对应实际可读取文件。必要时增加**最小**逐镜可用媒体导出或明确的受支持切片方案，使中立清单不仅是描述数据。版本化升级并保持 v1 可读；原子写、旧项目兼容和源资产不覆盖都要验证。没有许可编辑器时只完成清单和可用素材，不冒称完成编辑器往返。结果 `artifacts/handoffs/claude-video-studio-c2-result.md`。

## C3：W4 交互页触屏、可访问性和性能口径

用浏览器触屏模拟测试拖转与拆解，修复真实发现的问题；给交互控件键盘/焦点/可读名称和必要的状态反馈。补充首次加载时间、资源体积与帧率的可复跑测量，并区分无头软件渲染、桌面 GPU 与真机触屏；没有真机就保留「真机未测」。保留现有 8 MiB、自包含、离线与 iframe 约束，不为测试改成联网加载。结果 `artifacts/handoffs/claude-video-studio-c3-result.md`。

## C4：W3 Blender 路线的环境与双路线对照

重新查本机已安装 Blender、既有项目工具目录和历史样片。若可用，按 W3 协议跑准确模型或非品牌程序化对象的 Blender 双画幅渲染，与同题材 Three 路线做同机位对比，记录源文件、许可、命令、RTX 4060/CPU 实际使用情况、耗时和关键帧。若没有执行器，可在不改系统安装的前提下使用官方可信来源的便携版；下载/运行不成功就如实停在环境门禁，不无限重试。人工评分待人工时留空，不能宣称商业级产品广告。结果 `artifacts/handoffs/claude-video-studio-c4-result.md`。
