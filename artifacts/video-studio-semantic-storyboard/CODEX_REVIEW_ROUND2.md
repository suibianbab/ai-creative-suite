## 仍需修复

### P1：用户明确要求真实照片/素材时仍可能静默变成图解

`semantic-provider.ts:32` 明确指示模型遇到真实照片需求时“改用图解表述，不要造字段”。`route.ts` 对用户要求只做长度和时长解析；只要模型顺从上述提示输出合法图解 IR，`validateSemanticDraft` 的字段校验就会通过，路由返回成功分镜。新增的 API 测试只让假模型输出 `assetUrl` 字段，因此没有覆盖这一实际路径。

复现条件：请求句为“用真实产品照片制作短片”或“要真实照片的科普片”，假模型返回合法、无资产字段的图解 IR，路由会 200。与交接单“无法表达的资产请求明确提示，不猜”和报告“不再无声转通用图解”不符。

建议在规划前或模型响应中建立明确的能力边界结果：对必须使用真实素材的要求返回“需导入素材/人工选模板”，允许用户主动选择改为图解后才继续。用“用户要求真实照片 + 合法图解 IR”的 API 反例锁定，避免仅依赖模型输出未知字段。
