# Codex 复核：语义分镜首轮

复核范围：`655cbdf..9fc1e8f`，工作树 `claude/video-semantic`。结论：**暂不合并**。架构方向符合交接单，真实双画幅出片可用；以下问题需要收口。

## 必修

1. **P1：新 AI 请求期间旧确认卡仍可应用，失败后还会错标来源。** `page.tsx:943-952` 启动请求时只重置 `semanticPlan`，没有清除或冻结 `editor.storyboard`；`page.tsx:1041-1143` 继续显示旧卡，确认应用按钮也未按 `semanticPlan.busy` 禁用。复现：先成功生成 AI 分镜 → 修改输入 → 再点 AI 生成 → 第二次请求失败/等待期间，旧卡依然可确认；失败后 AI provenance 已清空，旧 AI 结果按 `planner-rules` 记账。修法：在请求开始时撤销旧候选，或把候选及其 provenance 绑定为单一带 requestId/sentence 快照的对象；请求期间禁止应用。加浏览器回归：成功→再次生成失败；成功→再次生成未完成时点确认；成功→更改输入后点确认。

2. **P1：IR 未实施交接单要求的未知字段/资产引用拒绝。** `semantic-storyboard.ts:83-183` 只检查已知字段，`shots.push(shot as SemanticDraftShot)` 还保留全部额外字段。模型输出 `{assetUrl, html, svg, params}` 或额外根字段会作为合法 IR 通过；目前编译器忽略这些字段，所以没有代码执行，但“需要真实照片/资产”的需求可能被无声转成通用图解。应对根、镜头、嵌套步骤做严格键集合校验，并对无法表达的资产要求给出明确拒绝/人工素材指引。补反例单测与 API 假响应测试。

3. **P2：受校验的 cycle caption 被静默丢弃。** `semantic-storyboard.ts:155-164` 接受每阶段 caption，`semantic-storyboard.ts:248-264` 编译时只保留 label。若模型把“蒸发吸热”等关键信息放在 caption 而旁白未重复，确认卡与成片会缺失。应从 IR 去掉 caption 并要求模型写进 label/旁白，或实现安全布局后上屏；验证确认卡与编译结果一致。

4. **P2：重试 token 用量未合计。** `route.ts:56-83,116-117` 第二次调用覆盖 `draftSource`，只返回最终调用 usage。报告称“usage 透传做计费台账”，但发生时长/IR 重试时低报成本。返回两次调用合计与分项，并用双调用测试锁定口径。
