# 通用自然语言图片编辑 — 完整解决方案设计

日期：2026-10-15 · 状态：v2 设计稿（可直接作为 codex 的实施需求）
前置讨论：本目录《进阶案例手册.md》+ 会话结论"补全而非转换"框架
v2 修订：依据 PhotoCraft 0.6.0 官方接口实测（README "Built for agents" + `photocraft-cli --help`），见 §12

## 0. 目标与"完整"的定义

**目标**：任意图片（房子/花/手机壳/…）+ 任意表述（口语/paraphrase/英文）→ 安全的精确编辑。

**完整的定义**：不是"全部自动"，而是**每一句输入都有确定的处置路径**：

| 输入类型 | 处置路径 |
|---|---|
| 主体级编辑（把主体/背景…） | **全自动**（rembg 已达标） |
| 部件级编辑（把屋顶/花瓣…） | **候选提议 + 一次点击确认** |
| 参数不全（提亮一点） | **默认值执行成调整层 + 滑杆交接**，永不追问数字 |
| 操作歧义（换色还是加滤镜？） | **追问**（唯一允许打断的情况） |
| 越界能力（去掉背景/生成/审美） | **体面拒绝 + 说明边界**，绝不半吊子执行 |

覆盖承诺：主体级 100% 自动；部件级 ≥90% 经一次确认解决；细粒度（毛发/瓦片）与审美意图明确降级（见 §8）。

## 1. 总体架构：五层管道

```
用户输入（任意自然语言）
  ↓ L1 意图解析      —— 操作封闭 / 目标开放 / 缺口显式标注
  ↓ L2 缺口分析      —— 分拣三类缺口：目标缺口 / 参数缺口 / 操作歧义
  ↓ L3 补全路由      —— 按缺口类型选最便宜的来源：
  │     目标缺口 → grounding 级联（图层名→主体→SAM+CLIP→人工画框）
  │     参数缺口 → 默认策略表 + 调整层预览 + 滑杆交接
  │     操作歧义 → 追问
  ↓ L4 验证双闸      —— round-trip 蕴含核对 + 解释确认 UI（渲染即终审）
  ↓ L5 执行          —— 非破坏调整层 + 版本 + 质量门 + 账本（现状保留）
```

L5 完全复用现有资产（调整层/撤销/版本/积分账本/租户隔离），本方案不动它——它是"允许系统适度地猜"的保险。

## 2. L1 意图解析：开放目标、封闭操作

**IR（中间表示）**——扩展现有 `PhotoCraftInstructionPlan`：

```ts
type GeneralPlan = {
  operation: RecolorOp | AdjustOp | CropOp | TextOp | ...;  // 封闭集，沿用现有 19 种
  target: {
    kind: "layer-ref" | "subject" | "background" | "region-np";
    phrase: string;            // 用户原话名词短语，不翻译不改写："屋顶"
  };
  protect?: { phrase: string }[];   // 保护清单，同样开放
  params: Partial<OpParams>;        // 允许缺槽位
  missing: ("target" | "amount" | ...)[];  // 显式缺口，交给 L2
  confidence: number;
};
```

**解析器链**（快慢双轨）：
1. **快车道 = 现有精确语法**（保留！说得准的用户零延迟零误判，正则即裁判）
2. **通用道 = 云端 LLM**（走已有 Provider 抽象）：schema 约束输出、temperature 0、few-shot 含 paraphrase/英文/口语样例；目标短语**原样保留**供 grounding，不做模型侧"翻译"
3. 本地小模型仅作离线兜底（无网环境），沿用现有严格校验

## 3. L2 缺口分析：把"模糊"形式化

对每个 IR 逐槽检查，产出缺口清单——**这一步是"补全而非转换"原则的代码化**：

- **目标缺口**：target 无法从上下文直接解析 → 进 grounding
- **参数缺口**：数值/颜色/尺寸缺失 → 永不阻塞，走默认+预览
- **操作歧义**：多个 operation 都说得通 → 唯一触发追问的情况

## 4. L3a Grounding 级联（方案的心脏）

按成本/可靠性**从上到下**尝试，每个解析器返回候选区域 + 置信度：

| 级 | 解析器 | 覆盖 | 新 ML 需求 |
|---|---|---|---|
| 1 | **文档上下文**：当前选中图层、已有选区/蒙版、图层名（PSD 导入的命名图层） | 命中时 100% 准 | 零 |
| 2 | **主体分割**：rembg（已部署 :4102） | 主体/前景/背景，**任意图片** | 零 |
| 3 | **开放词汇部件**：SAM 自动蒙版生成（出全部区域候选）+ Chinese-CLIP 文本-区域匹配排序 → top-3 | 屋顶/花瓣/任意名词部件 | 中（两个现成模型，接入+调参） |
| 4 | **人工画框/画笔**（现有交互） | 兜底，永远可用 | 零 |

**裁决规则**：top-1 置信度 > τ_auto 且该操作可一步撤销 → 自动；否则进**提议-确认环**。

**提议-确认环 UI（关键复用）**：把现有**蒙版审核面板升级为"目标审核"**——候选区域以编号高亮描边叠在画布上，用户点一下（或说"第二个"）；蒙版画笔仍可手工修。protect 清单走同一环。这把"识别不准"的未解决问题转化成"三选一"的已解决问题。

τ_auto 的校准：记录每个解析器的确认率/修改率，按解析器分阈值定期调（数据进现有 QA 体系）。

## 5. L3b 参数补全：默认 + 滑杆交接

- **领域默认策略表**（语法里已有雏形：一点=10、明显=25，抽出来做成数据表）：每种操作一组默认值 + 文档（"提亮一点"→brightness+10）
- 执行方式：**默认值直接生成调整层并出预览**，右侧面板自动聚焦对应滑杆
- 原则：**绝不向用户追问数字**。数字是滑杆的职责，不是语言的职责
- 唯一例外：`text` 操作缺文字内容（这是语义必需槽，无法默认）

## 6. L4 验证双闸（替代被拆掉的语法墙）

1. **Round-trip 蕴含核对**：IR → `describePhotoCraftPlan`（已有）生成中文描述 → LLM 判断描述是否被用户原话蕴含（操作/颜色/方向/幅度/保护逐项）。不一致 → 降级为解释确认。`reconcilePhotoCraftModelPlan` 的"参数从原话反查"逻辑保留，作为蕴含核对的硬校验子集
2. **解释确认 UI**：应用前展示「我理解为：把**屋顶**换成蓝色，保护**天空**。对吗？」与视觉预览并排，一次点击确认/纠正。**编辑器里渲染结果就是终审**——这一步拦截剩余 95% 误解析
3. 应用后质量门（现有 应用前质量检查）保留，作为最后一道网

多步指令：现有手写顺序约束（裁切最后/单局部步骤/保护紧跟）改造成**操作元数据表驱动的约束引擎**（每个操作声明前置/后置条件，如 crop 作废选区坐标），19 个操作规模下等价但可扩展。

## 7. 评测体系（没有这个，一切只是手感）

- **金标准集**：≥200 条（指令 → 期望 IR）对，覆盖：paraphrase、口语、英文、模糊指令、越界指令、多步、保护清单；图片覆盖非商品域（房子/花/家具）
- **指标**：解析准确率（IR 字段级）、grounding IoU@确认环、端到端成功率、平均确认次数、编辑放弃率
- **回归纪律**：换模型/改 prompt/调阈值必跑；纳入 `qa/registry.json` 一个新 tier
- **线上回流**：确认环的点击率、滑杆修改幅度、撤销率按解析器分桶统计（现有账本/遥测基础设施可承载）

## 8. 明确不做（降级矩阵）

| 能力 | 处置 | 理由 |
|---|---|---|
| 细粒度部件免确认（胡须/瓦片自动） | WAIT | IMG-019 量化未达商业验收，等模型进步 |
| 审美意图（更高级/更好看） | 转风格预设产品线，不进编辑指令层 | 属于生成/风格问题，不是编辑操作映射 |
| 空间关系指代（桌子左边那把椅子） | 候选环兜底，不承诺自动 | CLIP 空间推理弱，确认环可用 |
| 生成填充/扩图 | 走 AI_PROVIDER 分类（现有 watchlist 已定） | 不重复造 |

## 9. 实施里程碑（映射到本仓库）

| 里程碑 | 内容 | 新 ML | 解锁 |
|---|---|---|---|
| **M1**（1–2 周） | 目标字典加 主体/前景/背景 接 rembg；IR schema + L2 缺口分拣；快车道保留；评测集 v0（50 条） | 零 | **任意图片的主体级编辑立即可用** |
| **M2**（2–4 周） | 蒙版审核→目标审核 UI（提议-确认环）；云 LLM 解析道 + round-trip 验证；默认策略表 + 滑杆交接 | 低 | 任意表述 + 主体级；解释确认上线 |
| **M3**（4–8 周） | SAM+CLIP 候选服务（本地 GPU 或 API）；protect 清单 grounding；约束表重构 | 中 | 部件级编辑（屋顶/花瓣/局部） |
| **M4**（持续） | 评测扩到 200+、τ 校准回流、双轨遥测对比 | 低 | 可维护地加宽能力 |

## 10. 风险与对策

| 风险 | 对策 |
|---|---|
| SAM 候选生成延迟（秒级） | 上传图片时**异步预生成**全部候选蒙版，输入指令时已就绪 |
| Chinese-CLIP 中文匹配质量 | 评测集先行验证；不足则候选数从 3 放到 5，靠确认环吸收 |
| 云模型成本/延迟 | 快车道优先命中（语法精确匹配零成本）+ 相似指令缓存 |
| 置信度校准漂移 | 按解析器分桶的确认率回流，月度调 τ |
| 非商品域图片的 rembg 失败 | 级联第 4 级（人工画框）永远在，失败自动降级并提示 |

- `describePhotoCraftPlan` → round-trip 验证的描述生成器（已有）
- `MaskReview` 组件 → 目标审核面板（升级）

## 12. v2 修订：依据 PhotoCraft 官方接口（2026-10-15 实测）

PhotoCraft 0.6.0 官方定位"Built for agents"：同一 500+ 命令注册表之上提供 CLI `run`、常驻 `serve`（JSON lines，含 `doc.inspect/render/select`）、`batch`/`droplet`、`mcp`、`commands --json`（注册表自描述导出）、桌面 `--control`（loopback 认证 + 离屏截图）五种入口。官方立场：**引擎保持精确，语义归调用方**。据此修订：

### 12.1 保留不变（并获印证）

- 五层管道、快慢双轨、grounding 级联、round-trip 验证、责任分配——PhotoCraft 解决"选哪个命令/参数什么类型"，**不解决** grounding、参数出处、业务记账，应用层价值不变
- **不让前端/模型直连 MCP 开引擎**（ADR-0011 规则 1 同理）；有界 IR + capability-manifest 的 validate/commands/verify 契约保留

### 12.2 三处实质调整

1. **传输层：per-request `run` → 常驻 `serve` 会话**（M2 前置，纯infra）
   现桥接每次请求冷启动 CLI 进程（120s 超时）。改 `serve` 常驻会话：延迟大降，且获得 `doc.inspect/render` 能力（下条依赖它）。注意会话生命周期管理（现桥 maxActiveRequests=1 的串行约束平移为会话池）。
2. **滑杆交接绑定原生调整层 + 预览 = 引擎渲染**（升级 §5）
   原方案的"默认值→应用侧调整层→应用侧预览"改为：默认值生成 **PhotoCraft 原生调整层**，预览用 `doc.render` 离屏渲染，滑杆直接改原生调整层参数再渲染。**消除应用侧预览与引擎输出的对等性风险（preview = final）**，滑杆交接从"平行模型"变成"真参数"。
3. **操作封闭集从 `commands --json` 生成**（升级 §2）
   IR 的 operation 枚举不再手工维护 19 种：锁版本 → 导出注册表 → 与 capability-manifest 做 diff → 生成候选扩容清单（按 watchlist 分级逐个放开，每个新操作仍须自建 validate/commands/verify 三段契约后才进 IR）。升级 PhotoCraft 版本时注册表 diff 纳入现有 pin+回归纪律。规划模型的输出约束直接引用官方 schema（参数类型/范围来自注册表，§2 的参数缺口检测随之 schema 化）。

### 12.3 两处新增能力线

4. **批量配方（确认一次，套全目录）**：单图上经确认环通过的动作列表，经 `batch --actions` 一键应用到整个目录——电商天然场景，PhotoCraft 原生支持。计费按张入账本，质量门抽样复检。
5. **评测驱动真引擎**（升级 §7）：200 条金标准不止测"解析出正确 IR"，而是经 `serve`/`mcp` **真实执行到引擎**，测端到端成功率与 verify 通过率。MCP 作为 QA/评测 harness 的驱动通道（非产品运行时）。

### 12.4 里程碑增量

| 里程碑 | v2 增量 |
|---|---|
| M1 | 不变（零 ML，先解主体级） |
| M2 | 前置：桥接改 `serve` 常驻会话；滑杆/预览按 12.2-2 重做 |
| M3 | 不变（SAM+CLIP）；grounding 第 1 级"文档上下文"升级为 `doc.inspect` 实时会话状态（含 PSD 命名图层） |
| M4 | 新增批量配方线 + 评测接真引擎；`commands --json` 注册表同步流程纳入版本升级纪律 |
